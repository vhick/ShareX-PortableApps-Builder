# ShareX PortableApps Builder Kit — Independent b1r1

**Mode:** PORTABLEAPPS only. **Not** a native-source-rebuilt ShareX application.

This is a complete **builder-source kit** for GitHub Actions: no generated binaries are committed. The hosted Windows runner downloads the official upstream ShareX x64 portable ZIP, verifies the developer-published SHA-256, builds a real **NativeAOT** `ShareXPortable.exe`, creates a ZIP, then invokes **exactly** the pinned shared NSIS installer and publisher actions. It produces an **independent PortableApps-style package, not an officially certified PortableApps.com package**. You need no local compiler.

**Important:** ShareX portable mode requires the app's working profile to be beside `ShareX.exe`, not directly in `Data`. The launcher temporarily moves `Data/ShareX` to `App/ShareX/ShareX` before launch and moves it back only after the ShareX process exits. This preserves completely empty directory trees and avoids broad host harvesting. It is a same-volume rename, not a cross-volume copy. **An interrupted session must be recovered by launching `ShareXPortable.exe` again BEFORE applying an installer or replacing `App`.** The shared installer cannot block upgrading a crashed package whose unsaved working profile remains in `App`. Never use an installer to recover this state; see `docs/RECOVERY.md`.

## First run with GitHub Desktop (Windows)

1. Open GitHub and create a **new repository** named `ShareX-PortableApps-Builder`. It must **not** be a fork of ShareX. Select Public or Private yourself. Keep it private if you do not want the code and releases visible.
2. Open GitHub Desktop, select **File → Clone repository**, and clone the new repository. You do not need `git init` or Git commands.
3. Extract `ShareX-PortableApps-Builder-Kit-b1r1.zip` into the local repository folder. You should see `README.md`, `launcher`, `scripts`, `docs`, `tests`, and a **hidden `.github/workflows`** folder at the repository root. Don't nest an extra kit folder inside the repository.
4. In GitHub Desktop, write a commit message such as `Add ShareX PortableApps builder`, then click **Commit to main** and **Push origin**.
5. Open your GitHub repository → **Actions** → **ShareX PortableApps - Verified Build and Release** → **Run workflow**. Use `latest` for the newest stable version; to pin a version, enter e.g. `22.3.0` (no `v`). Keep **Publish** checked to create a release; uncheck to validate without uploading.
6. Watch the job log. `STATIC-VALIDATED` means package structure, PE signatures, checksums and ZIP integrity passed. The synthetic launcher self-test does not prove ShareX's interactive features work.
7. If successful with Publish on, go to the repository's **Releases** and get the `ShareXPortable_...zip`, `ShareXPortable_...paf.exe`, and publisher-created `SHA256SUMS.txt`. Verify your downloaded SHA-256 against that manifest. Nothing is published if installer validation fails; a validated ZIP is kept temporarily as a workflow artifact for 3 days.
8. For ZIP use, extract **the `ShareXPortable` root folder** into your preferred PortableApps directory. Run `ShareXPortable.exe`, not `App/ShareX/ShareX.exe`. For the `.paf.exe`, run the separate **independent** installer and choose the destination; it is not PortableApps.com-certified.
9. If PortableApps Platform does not display the new application, refresh its menu. You can also launch the compiled root executable directly.
10. Before an update: use ShareX tray menu **Exit** (closing the main window may only minimize to tray); make sure `Data/ShareX` exists and `App/ShareX/ShareX` **does not**. Copy `Data` to a backup. Only then install/replace application files. For rollback, repeat this shutdown/recovery/backup check; reinstall the older application files but preserve the current `Data` backup. Older ShareX might not understand a newer settings database: restore the matching older data backup if necessary.

## Outputs / naming

- ZIP: `ShareXPortable_<version>_custom-nsis-b1r1.zip` (real full PortableApps directory)
- Installer: generated by shared Package Builder with actual filename `ShareXPortable_<numericPackageVersion>_custom-nsis-r1.paf.exe`
- Release tag: `sharex-portable-v<version>-<first12tagcommit>-custom-nsis-b1r1`
- Both download SHA-256 values: publisher-generated `SHA256SUMS.txt`
- Static machine-readable ZIP evidence: `dist/verification.json` in runner (not a release file)

At the time of authoring, latest **stable** is ShareX **v22.3.0** (November 7, 2026). Do not assume this version stays latest; the workflow queries official GitHub Releases and sorts version components numerically, excluding prereleases and drafts.

## What this project does and does not do

- Uses an official vendor `ShareX-X.Y.Z-portable-x64.zip` asset, validated against the SHA-256 the vendor publishes in the corresponding release notes.
- Validates the tag's exact 40-character commit, downloads and includes a source ZIP for that commit, records provenance and licenses, and includes the complete independent launcher source.
- Compiles a real Windows x64 launcher under .NET 10 NativeAOT. `ShareX.exe` is **not rebuilt from source**; that is allowed for the selected PORTABLEAPPS mode.
- Forces `-portable` with ShareX's documented source-verified mode, preserving normal CLI arguments except `-multi`/`-m` (deliberately disallowed with a single shared profile). ShareX's source skips its automatic extension registration in portable mode.
- Avoids changing global `%APPDATA%`, `%LOCALAPPDATA%`, `%TEMP%`, registry, Windows Startup, default-browser settings, associations, or installed ShareX profiles.
- Uses no ShellGuard cleanup because ShareX's normal portable startup needs none for app-owned configuration, and user-activated Windows integrations should not be silently undone. Custom integrations, Windows shell histories, API credential portability, and child-tool writes remain subject to acceptance tests.
- Leaves user-selected custom screenshot folders, external programs, network/upload destinations and extensions untouched. If user changes the screenshot path outside the portable folder, the launcher does not attempt to move it.
- Does **not** enable Windows startup or context-menu integrations. If you turn these on inside ShareX's settings, ShareX can create shortcuts/registry entries pointing directly at `App/ShareX/ShareX.exe`. This can bypass the wrapper on later starts, corrupt its one-profile assumptions or conflict with an installed ShareX. **Leave these disabled** in this edition.
- The ShareX tray process and background children are not forcibly killed. Root launcher tracks `ShareX.exe` and basic restarts by executable path, but cannot guarantee every external capture/encoding helper has exited. Inspect long-running recordings before closing or upgrading.
- Leaves normal Windows-owned icon caches, notification histories, Explorer state, task switcher/Jump List residue, GPU/runtime and third-party subprocess state outside scope. No zero-host-traces claim.

## Status and evidence

This ZIP builder kit was syntactically inspected on Linux with Python and YAML; no Windows native compiler, interactive ShareX GUI, NSIS execution or GitHub Actions execution was available in the authoring environment. **Therefore full end-to-end application functionality and portability are not yet verified.** CI can verify build + static package structure + a synthetic launcher controlled test. Actual program use, no host leftovers, tray, notifications, recorder, uploads, installed ShareX coexistence, real install/reinstall and app upgrades must be tested on Windows. See `docs/ACCEPTANCE.md`.
